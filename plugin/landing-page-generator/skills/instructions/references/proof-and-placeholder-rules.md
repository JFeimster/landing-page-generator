# Proof And Placeholder Rules

## Core Rule
Never invent proof. If the user has not supplied it, label it as a placeholder or omit it.

## What May Be Used Only When User-Supplied
- Testimonials
- Customer logos
- Case studies
- Revenue figures
- Customer counts
- Awards
- Certifications
- Press mentions
- Retention metrics
- Conversion metrics
- "As seen in" claims

## What Must Never Be Invented
- Real customer names
- Real company logos
- Real screenshots of results
- Real awards
- Real endorsement language
- Fabricated timelines
- Fabricated discounts or comparison prices

## Testimonial Rules
- Use exact wording when possible.
- Preserve tone and meaning.
- Do not combine multiple people into one quote.
- If quote is incomplete, use `[Testimonial placeholder]`.

## Logo Rules
- Use only logos the user has permission to display.
- If brand permission is unknown, use text placeholders.
- Never recreate a brand mark from memory.

## Case Study Rules
- Include the problem, the action, and the result only if the user supplied them.
- If the result is missing, present the section as a story or process example, not a results claim.

## Revenue And Count Claims
- Use exact numbers only if supplied.
- If exact values are private, do not approximate.
- Do not convert "small" into a fake count.

## "As Seen In" Rules
- Only use real publications or platforms.
- Publicly visible mention must be verifiable.
- If not verified, use `[Publication placeholder]`.

## Awards And Certifications
- Display only if confirmed.
- Avoid implying accreditation beyond the actual scope.

## Regulated Industries
For financial, medical, legal, and similar offers:
- Use conservative language.
- Avoid outcome guarantees.
- Avoid treatment or earnings promises.
- Add a note that final legal/compliance review may be required.

## Claim Safety Examples
### Unsafe
"Increase revenue by 300%."
### Safer
"Designed to improve conversion clarity and reduce friction."

### Unsafe
"Trusted by Apple and Nike."
### Safer
"Trusted by teams in SaaS, services, and ecommerce." 

### Unsafe
"Guaranteed to double your leads."
### Safer
"Built to support better lead capture through clearer messaging."

## Placeholder Formats
- `[Insert testimonial from customer]`
- `[Logo placeholder: customer list]`
- `[Enter exact price]`
- `[Add case study here]`
- `[Deadline placeholder]`
- `[Insert proof point]`

## Proof Escalation Checklist
If proof is missing, ask for:
1. Testimonials
2. Case studies
3. Before/after examples
4. Customer logos
5. Independent review links
6. Public results pages

## Claim Audit Checklist
- Is the claim factual?
- Is it user-supplied or publicly verifiable?
- Is there a placeholder if not?
- Could the claim be misleading out of context?
- Is the claim safe for the industry?
- Does the page need a disclaimer?

## Safe Use Pattern
When a proof element is unavailable, write the section like this:
- "Proof placeholder: add a customer quote here."
- "Logo row: insert approved client logos."
- "Results section: replace with a real case study before publishing."

## Final Rule
The absence of proof should never result in fabricated confidence.
