# Offer Stack Framework

## Purpose
Turn the offer into a clear, high-value package that makes the buying decision easier.

## Core Components
- Core offer
- Primary outcome
- Deliverables
- Bonuses
- Guarantee or risk reversal
- Payment options
- CTA

## Order Of Presentation
1. Main promise
2. What is included
3. Why it is valuable
4. Bonuses
5. Risk reversal
6. How to act now

## Rules For Missing Information
- If price is unknown, use `[Enter price]`.
- If bonuses are unknown, omit them.
- If guarantee is unknown, do not invent one.
- If deliverables are vague, ask the user to clarify.

## Ethical Rules
- Do not inflate value with fake retail numbers.
- Do not add bonuses that do not exist.
- Do not imply scarcity unless it is real.

## Value Framing
- Explain outcome value, not just feature count.
- Show how the offer saves time, reduces risk, or improves results.
- Use simple language the buyer can verify.

## Payment Options
- One-time payment
- Installment plan
- Subscription
- Retainer

Only use payment structures the user actually offers.

## CTA Strategy
- Match CTA to buyer readiness.
- Use "Get the draft" for early-stage interest.
- Use "Buy now" only for direct ecommerce or clear purchase flows.
- Use "Book a call" for consultative offers.

## Example Offer Stacks
### SaaS
- Core app access
- Templates
- Onboarding guide
- Support

### Coaching
- Core training
- Office hours
- Workbook
- Community access

### Agency
- Strategy session
- Page copy
- Revision round
- Launch notes

### Local Service
- Inspection
- Service call
- Parts and labor details
- Warranty or service guarantee if real

### Ecommerce
- Product
- Shipping details
- Return policy
- Bundle discount if real

## Strong Offer Stack Language
- "Includes"
- "Also get"
- "Bonus"
- "Built in"
- "Optional"
- "Available when"

## Weak Offer Stack Language
- "Amazing value"
- "Unbeatable"
- "Huge savings" without proof

## Final Rule
The offer stack should make the offer easier to understand, not louder.
