# Content and Conversion Strategy

Landing pages can use the existing three phases: gather only missing offer/audience/price/objections/proof inputs, summarize, write copy, then produce HTML. Honor whichever current GPT or plugin entry point the user invokes; see [integration-map.md](integration-map.md) for unresolved transition differences. API and dashboard projects use their own brief and do not need this sequence.

Map audience and awareness to a clear promise, mechanism and single next step. Translate features into benefits, use supplied objections for FAQ, and show available proof near the relevant claim. Mark assumptions and request evidence for logos, testimonials, metrics, guarantees, prices, inventory and deadlines. Never create customer identity or implied endorsement. A countdown requires a user-supplied deadline and expiry behavior.

For inaccessible URLs report what could not be inspected; distinguish observed content from interpretation. Use existing `knowledge/section-by-section-copy-framework.md`, `knowledge/proof-and-placeholder-rules.md`, and `knowledge/voice-of-customer-processing.md` as implementation references.
