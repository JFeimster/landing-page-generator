# Repository integration map

| Area | Current evidence | Role |
|---|---|---|
| Plugin | `plugin/landing-page-generator/` | Canonical identity, presentation, skill, icon, and 19 references. |
| Service contracts | `services/src/registry.ts`, `schemas.ts` | Source for 12 implemented deterministic utility operations. |
| Service interfaces | `services/src/routes.ts`, `services/src/mcp.ts` | Existing HTTP compatibility routes and Streamable HTTP MCP adapter. |
| OpenAPI | `services/src/openapi.ts`, `actions/` | Generated compatibility contracts. |
| Templates | `templates/`, `site-factory/templates/` | Reusable HTML assets and template specifications. Verify each asset before claiming runtime generation. |
| Catalogs | `data/`, `site-factory/catalogs/` | Structured strategy and project-selection metadata, not a project generator. |
| Examples | `examples/`, `site-factory/examples/` | Illustrative samples, not proof of measured outcomes. |
| Historical GPT material | `gpt/`, `gpts/`, legacy docs | Background for migration; not the active installation process. |

The package preserves existing templates, design packs, knowledge, catalogs, and examples. Assets may inform requested deliverables across static landing pages, lead funnels, SaaS/waitlist pages, directories/resource hubs, embeds, and Next.js scaffolds. Only the 12 registry utilities are executable service tools; the broader project types are not automatically generated by this repository.
